# 停止本轮生成（方向一）执行计划

## 目标

为 HTML、MULTI_FILE、VUE_PROJECT 三种生成类型增加“停止本轮生成”能力：用户主动点击停止后，后端精确取消当前回合的模型、文件工具和构建动作，原 SSE 连接继续作为唯一业务终态通道，并最终持久化可信的 `CANCELLED` 回合。取消不支持断点恢复；已落盘的 Vue 文件保留，HTML/MULTI_FILE 未完成的代码缓冲区不落盘；取消不会刷新前端预览。

## 不变约束

- 现有生成、工具调用、构建、记忆投影和 SSE 事件语义保持不变。
- 取消必须按 `(appId, generationId)` 精确匹配，不能只按 `appId`，避免旧请求取消新回合。
- 正常完成、异常、超时、客户端断开和用户主动取消都必须释放任务注册与应用生成租约。
- 原有未提交修改必须保留，不做无关重构。
- 不在取消接口中重复创建 AI 消息；由原生成 SSE 回合认领唯一终态并持久化。

## 实施阶段

### 1. 计划与现状基线

- 保存本计划到 `.codex/plans/`。
- 读取现有生成入口、回合上下文、取消协调器、终态持久化、前端会话和 API 契约。
- 记录当前工作区已有改动，后续只围绕本功能修改。

### 2. 统一生成任务身份与注册

- 在生成请求中增加必填字符串 `generationId`，前后端均按字符串处理。
- 新增轻量任务注册组件，按 `(appId, generationId)` 注册活跃任务，并提供幂等注销和精确取消。
- 注册句柄暴露统一取消入口；注册失败、正常完成、异常、取消和超时均注销。
- Vue 句柄委托现有 `VueTurnCancellationCoordinator`；HTML/MULTI_FILE 句柄委托 `SimpleGenerationTurnContext`，不复制底层租约逻辑。
- 取消接口只允许当前用户操作自己的应用，并返回“已请求/不存在/已结束”这类可判定结果；迟到取消不得影响新回合。

### 3. 后端生成接口与三类回合

- `/app/chat/gen/code` 接收并校验 `generationId`，把它传入服务层。
- 新增 `POST /app/chat/gen/cancel`，请求包含 `appId` 和 `generationId`。
- Vue 回合注册后使用现有回合取消 CAS、模型取消、文件工具取消、构建取消、静默等待和 `VueTurnFinalizer`，由原 SSE 发出 `CANCELLED` 终态。
- HTML/MULTI_FILE 回合在取消时停止模型流，丢弃未完成代码缓冲区，清理不可信 L0，并补齐稳定 `CANCELLED` AI 消息，避免只留下孤立用户消息。
- 取消发生在用户消息提交前时只清理准备资源，不写入 AI 终态；提交后必须写入 `CANCELLED`。
- 保证每个终态只执行一次持久化和内存钩子，结束后注销任务。

### 4. 前端停止交互与会话协同

- 生成请求为每次回合生成 UUID，并在请求体携带 `generationId`。
- 生成中发送按钮切换为停止按钮；停止请求中显示“正在停止…”并禁止重复点击和新发送。
- 新增取消 API 调用，取消接口失败时保留生成状态并提示失败，不能假装已取消。
- 不直接以 `AbortController.abort()` 作为业务取消；等待原 SSE 收到可信 `CANCELLED + done` 后再清理会话。
- 取消终态不刷新预览；正常成功终态仍按现有规则刷新。
- 页面卸载/网络断开继续沿用现有客户端断开逻辑，不改变后端业务终态规则。

### 5. 测试与验证

- 后端补充 DTO、任务注册、取消精确匹配、Vue/普通回合取消终态、重复/迟到取消测试。
- 前端补充请求契约、停止按钮状态、取消请求失败、收到 `CANCELLED` 后清理会话且不刷新预览测试。
- 运行相关 Maven 单元测试、前端类型检查/单元测试/构建，并检查当前已有改动未被覆盖。
- 用代码审计确认三种模板均满足：模型取消、未完成内容处理、唯一 `CANCELLED` 终态、租约和注册注销。

### 6. Git 提交

- 仅提交本功能相关文件及本计划文件；不提交与本任务无关的既有改动，除非它们本来就是用户要求保留并已在同一工作区中需要一并提交。
- 提交信息使用全量中文，格式参考历史提交。
- 未经用户再次明确授权不推送远端。

## 风险与处理

- 取消接口与原 SSE 并发时以回合终态 CAS 为准，避免重复 AI 消息。
- generationId 缺失或重复直接拒绝，避免无法关联取消或覆盖活跃任务。
- 取消接口网络超时不代表业务取消成功，前端必须等待 SSE 终态或明确提示用户重试。
- 普通模板的取消终态写入必须与原用户消息处于同一应用生命周期写门内，避免删除或新回合竞态。
