# 32K 工具读取循环根因修复实施计划

> 本计划固定用户已经确认的最终方案。实施期间继续使用 `28672 / 30720 / 32768`，不恢复 64K 阈值。

## 目标

修复未完成工具链进入 32K 可信检查点后，因为刚返回的 `readDir/readFile` 结果被投影删除，导致模型连续重复读取同一路径的问题；同时增加确定性的重复读取纠正与安全熔断，避免模型异常时消耗完整的 64 次工具/模型上限。

## 已核实根因

- 故障回合实际执行 `readDir("src")` 54 次、`readFile` 9 次、`writeFile` 2 次。
- 模型返回的是真实结构化 `tool_calls`，不是前端重复渲染，也不是普通正文中的伪工具调用。
- 达到 `32768` 后，`ContextCompressionCoordinator` 在每次续请求重建检查点。
- `UnfinishedToolChainCheckpointProjector` 只保留“已读取路径”等事实，删除刚完成的真实目录/文件读取结果。
- 下一次模型请求看不到刚才的结果，只能再次调用同一读取工具，形成真实工具循环。

## 全局约束

- 只修改当前工作树，不覆盖用户已有改动，不清理 `.codex/` 材料。
- 禁止 `git add .`、`git add -A`、`git clean`、`git reset --hard`，未经允许不 push。
- 保持阈值 `async=28672`、`blocking=30720`、`hard=32768`。
- 检查点仍是本次模型请求的临时视图，不写入 Redis、L0、L1、L2 或 MySQL。
- 所有新增行为先写失败测试并观察预期失败，再写最小实现。
- 重复读取兜底只覆盖受信的 `readDir/readFile` 结构化调用与 `file-tool/v1` 结果，不扩大到写文件或构建工具。

ToolExecutionResultMessage：与调用 ID 完整配对的真实读取结果

## 任务 3：重复读取指纹与回合内状态机

### 指纹

```text

  工具名称
  + 规范化 JSON 参数

)
```

- 不包含 `tool_call.id`。
- 参数 JSON 采用稳定键顺序；结果只接受通过可信解析器校验的 `file-tool/v1` 文本。
- 指纹和计数只在当前用户回合内存活，不进入持久记忆。
