# Vue RAG 全分支终审修复规格

## 背景与目标

全分支只读终审范围 `5850ef9..082e1ba` 发现 5 项 Important。当前代码的默认 Maven 与 PGVector 协议探针已通过，但这 5 项会让错误知识目录进入生产、让真实门禁连接错误数据库凭据、让十条生成绕过前置质量条件、让旧通过报告污染本轮审计，或让标准生产部署无法开启 Hybrid。

本轮目标是在不扩大原 Vue RAG 范围的前提下关闭全部 5 项 Important，并保持以下事实边界：

- 正式 23 条 `text-embedding-v4` 摄取尚未执行。
- 30 条真实检索尚无达标成绩。
- 十条首次真实生成尚无 10/10 构建成绩。
- 缺少真实模型凭据时，只能判定代码门禁状态，不能判定可发布。

## 方案选择

### 采用方案：同轮结构化门禁编排

生成门禁在同一 JVM 进程、同一次运行内依次执行：

```text
当前知识目录加载与 23 条物理摄取核验
→ 30 条真实 Hybrid/Dense-only 检索并要求 passed()
→ 启动生成 Spring 上下文
→ 十条首次生成与构建
```

前两步均返回 Java 结构化结果并直接交给下一步，不读取历史 Markdown。任何一步未执行、未通过或抛异常，后续外部模型、Spring、应用生成与 npm 构建均不得启动。

### 不采用的方案

- 不解析上一轮 Markdown 报告：报告是给人和发布审计消费的输出，不是可信程序状态；它可能陈旧、损坏或来自不同目录版本。
- 不只依赖人工执行顺序：无法阻止空表、22 行或旧目录版本下误跑生成。
- 不回退 `SPRING_DATASOURCE_PASSWORD`：生产配置已把它定义为 MySQL 密码，静默兼容会继续掩盖错误部署。

## 需求 1：收紧知识目录契约

`TemplateCatalog` 必须在创建知识块和可信摄取快照前拒绝结构不完整的文档：

- `schemaVersion` 只支持整数 `1`；缺失、`null`、其他版本均拒绝。
- `version`、`framework`、`language`、`buildTool` 必须为非空白文本。
- `dependencies`、`devDependencies` 可以缺失或为 `null`，其语义统一为空 Map。
- 依赖 Map 中禁止 `null` 键、空白键、`null` 值和空白版本值。
- 错误信息必须带来源 JSON 相对路径和具体字段名。
- 现有 18 个父文档、23 个知识块与 `schemaVersion: 1` 必须继续加载成功。

## 需求 2：RAG 专用 PGVector 密码

三类真实门禁统一只读取：

```text
RAG_PGVECTOR_PASSWORD
```

涉及范围：

- 正式 Vue 摄取门禁。
- 真实 Vue 检索门禁。
- 十条真实生成构建门禁。
- PGVector JDBC verifier、EmbeddingStore 和评测 Spring 属性注入。
- 环境模型测试、报告允许原因、设计文档、实施计划和命令示例。

`SPRING_DATASOURCE_PASSWORD` 可以同时存在且值不同，但不得被任何 RAG PGVector 门禁读取。缺少 `RAG_PGVECTOR_PASSWORD` 时，必须在端口探测、数据库连接、模型创建和 Spring 启动之前短路。

## 需求 3：生成门禁 fail-closed 前置

十条生成门禁必须复用现有可信目录快照和物理核验能力，再运行同轮真实检索。验收语义：

- `templates_vue` 不存在、为空、只有 22 行、目录版本不匹配、向量维度或五键 metadata 不符时，不得启动 Spring 或生成服务。
- 摄取物理核验通过，但真实检索报告为未执行或未达到门槛时，不得启动 Spring 或生成服务。
- 只有摄取核验 `passed()` 且真实检索报告 `passed()` 时，才能加载十条数据集、启动 Spring、调用生成与 npm 构建。
- 前置编排应提取为可注入 Supplier/协作者的普通 Java 类，以便单元测试证明调用顺序和短路边界；测试不能依赖真实模型或数据库。
- 生产运行仍保留原有可用性降级；fail-closed 只属于质量门禁，不改变在线生成语义。

## 需求 4：报告生命周期与原子写入

真实检索和十条生成报告必须表示本轮状态，不能遗留上一轮通过结果：

- 每次门禁测试开始时立即写入本轮“未通过/运行中失效”报告，覆盖旧结果。
- 环境开关未启用或凭据不全仍写“未执行”。
- 目录、数据集、物理核验、模型/服务创建、Spring 启动或评测异常时，写本轮“未通过”报告后重抛原异常。
- 报告包含非秘密的运行 ID 或开始时间，能区分本轮与上一轮。
- 报告写入必须先写同目录临时文件，再以原子替换覆盖正式文件；文件系统不支持原子移动时允许同目录替换降级，但不得先删除旧报告后留下空窗。
- 报告继续经过统一脱敏器，禁止输出密钥值、用户绝对路径或完整异常敏感文本。
- 测试必须预置旧“通过”报告，再制造目录/数据集/核验/模型或 Spring 前置异常，证明旧报告被本轮失败结果覆盖。

## 需求 5：生产 Hybrid 开关

标准生产配置补齐以下变量：

`prod/docker-compose.yml`：

```yaml
RAG_HYBRID_ENABLED: ${RAG_HYBRID_ENABLED:-false}
```

`prod/.env.example`：

```env
RAG_HYBRID_ENABLED=false
```

`prod/README.md` 必须给出可执行启用顺序：

```text
正式摄取通过
→ 真实检索通过
→ 十条生成 10/10
→ RAG_HYBRID_ENABLED=true
→ 重启 backend
```

默认值必须保持 `false`。不得在缺少三项真实成绩时自动或默认开启。

## 错误处理与安全边界

- 环境模型仅保存就绪状态、受控原因和非秘密 PGVector 目标，不保存密码值。
- 报告不得渲染原始环境 Map、连接串密码或第三方模型错误正文。
- 异常报告写入失败时，不得吞掉原业务异常；应以原异常为主，并把报告写入异常加入 suppressed。
- 不访问工作区外凭据，不搜索钥匙串或 Shell 历史，不创建假向量或假真实指标。

## 测试与验收

必须按 TDD 逐项保留 RED 与 GREEN 证据，至少覆盖：

1. `TemplateCatalogTest`：schema、五个工程元数据字段与依赖键值边界。
2. 三类环境测试：只认 `RAG_PGVECTOR_PASSWORD`，MySQL/PG 密码不同也不串用。
3. 生成前置编排测试：物理核验失败、检索未执行、检索未达标均短路；全部通过才执行生成。
4. 检索与生成报告测试：明确“未通过”、运行标识、脱敏。
5. 报告写入测试：预置旧通过报告，异常后由本轮失败报告原子覆盖。
6. 生产配置静态测试或等价验证：Compose 与 `.env.example` 默认关闭，README 有完整启用顺序。
7. 相关定向测试和完整 Maven 均使用项目 JDK 25；PGVector 相关 JVM 使用 `-DsocksNonProxyHosts=localhost|127.*|[::1]`。

## 完成定义

- 最新全分支独立复审中 Critical=0、Important=0。
- 完整 Maven fresh 运行通过，测试数与跳过数如实记录。
- `.codex/sdd/progress.md` 和 `.codex/sdd/whole-branch-review.md` 不再保留“当前代码可合并”的过时结论；只有新终审清零后才能重新写入代码合并结论。
- 缺少模型凭据时，最终状态仍必须写为“不可发布”，并列出三项未取得的真实成绩。
