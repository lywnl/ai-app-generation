# 企业官网

围绕“理解企业业务、判断是否适合、发起联系”组织内容和操作，让访客能够了解具体服务及可信依据。

## 任务规则

1. 根据行业、目标客户和当前需求组织公司、服务、新闻、案例与联系页面。首屏明确企业名称、具体业务和主要行动入口，不用空泛口号代替服务说明。
2. 产品服务、新闻和案例使用稳定 ID，列表与详情保持名称、图片和内容一致。详情进入对应内容，不让所有入口跳到联系我们或同一占位页面。
3. 需要轮播时，每张表达不同信息，并提供可操作的切换控制；避免高速自动播放，移动端仍能操作，不让轮播成为阅读必经障碍。
4. 案例说明客户问题、解决方案与结果；公司资质、客户背书、团队履历和经营数据来自已提供材料。缺少材料时使用明确的演示内容，不编造真实合作、奖项或业绩。
5. 多语言切换覆盖导航、正文、按钮、表单、校验和反馈；切换时保留当前页面及用户已填写内容，不翻译用户输入，不只切换语言按钮文字。未指定语言时默认中文，可提供明确的中英演示，不新增国际化依赖。
6. 联系表单根据已有业务要求校验，提交期间防重复，失败保留内容并允许重试；缺少接收服务时明确未真实发送，电话、邮箱、地址只使用真实提供值或明确示例。
7. 客服区分常见问题、本地交互演示与真实服务。静态答复不能冒充人工在线或真实 AI 客服，不伪造已转接、已送达和服务时效承诺。

## 本项目边界

遵守宿主 System Prompt、RAG 骨架、依赖白名单和工具协议，不增加依赖或权限。只实现当前需求，局部修改不扩建整站；不调用其他 Skill，不假设浏览器或外部服务可用。缺少后端时明确演示，不伪造认证、保存或发送结果；默认使用简体中文，多语言按需求切换。

## 完成自检

服务和新闻详情是否对应，语言切换是否覆盖正文及反馈，联系和客服是否如实表达发送状态，案例是否存在虚假背书。只声明已有工具结果能证明的验证。
