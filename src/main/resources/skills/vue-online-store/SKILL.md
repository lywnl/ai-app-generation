# 在线商城

围绕“找商品、确认商品、加入购物车、确认结算、查看订单”串联功能，确保数据和金额一致，不将前端演示冒充真实交易。

## 任务规则

1. 按需求实现商品发现与购买路径，各页面共享一致的商品数据和稳定 ID；商品评价归属对应商品，详情不能共用占位内容。搜索、分类、排序和分页共同生效，条件改变时重置分页。
2. 有规格时以商品 ID 与规格组合标识购物项，同规格再次加入合并数量，不同规格分别记录。必选规格未选齐不能加入，数量必须为正整数；库存约束仅来自已有真实数据或明确演示数据。
3. 数量变化、勾选、删除同步更新购物车数量与结算金额；处理空购物车、无选中商品和商品不可用。没有可结算商品时不能创建订单。
4. 金额以整数最小货币单位计算，展示时统一格式化。结算明确商品金额、优惠、运费与应付金额；优惠不重复扣减，应付额不为负，不擅自确定税费或运费业务规则。
5. 优惠券明确门槛、范围和有效性，购物项变化后重新校验；积分规则来自需求，未提供时只使用清楚标识的演示规则，不将演示积分当作真实资产。
6. 创建订单时复制商品、规格、数量和价格快照，后续购物车或商品变化不改写历史订单。订单详情与状态对应提交结果，避免重复点击生成重复订单。
7. 注册登录没有认证服务时只表达演示会话，不保存或记录密码，不把前端登录状态当作权限保障；有真实接口时遵循其契约，不猜测接口地址或认证规则。
8. 支付、库存扣减、积分入账依赖真实服务确认。没有服务时提供明确的模拟结算及模拟订单状态，不能显示真实扣款、支付成功或订单已发货；演示状态变化保持一致。

## 本项目边界

遵守宿主 System Prompt、RAG 骨架、依赖白名单和工具协议，不增加依赖或权限。只实现当前需求，局部修改不扩建整站；不调用其他 Skill，不假设浏览器或外部服务可用。不擅自建立支付、库存、权限和持久化规则；默认使用简体中文。

## 完成自检

不同规格是否隔离，数量和优惠变化是否正确重算金额，订单是否保留快照，认证及结算是否如实标识演示。只声明已有工具结果能证明的验证。
