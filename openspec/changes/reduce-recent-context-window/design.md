# Design

## Context

动机和来源见 proposal。当前 `MemoryTokenProperties` 的默认值与严格校验共享 `REQUIRED_L0_RETAINED_TOKENS=12_288`，`application.yml` 同样配置 12288。`SummaryWindowSelector` 与旧完整回合选择器通过共享配置取得目标，不需要改变算法。`cd32ab7` 已包含热窗口计划恢复。

## Goals / Non-Goals

- 实现规格“近期原文必须跨回合按 Token 保留”和“近期原文预算配置必须一致”，保留原有预算一致性检查。
- 不动态调参、不扩展摘要、不改窗口条目、回收事务、计划身份、缓存编码或工具协议。

## Decisions

1. 同时将固定默认值及 YAML 更新为 8,192。仅改 YAML 会启动失败；改成任意正数可调会扩大本次约定，因此保持精确校验。
2. 沿用选择器的完整单元与保护逻辑。新增精确 8,192／8,193 边界测试，回归最新超目标、未完成批次及用户原话保护。其他泛用选择器测试中的独立样例预算不自动视为生产配置，不做无意义全局替换。
3. 更新生产预算断言，真实模型验收夹具从实际配置读取 retained 值，删除当前代码注释中的固定 12K 表述。新增 YAML 加载验证，避免默认值与资源配置再次分离。
4. 验证采用项目 Java 25、Maven 离线缓存与 JUnit。运行配置、窗口、压缩协调／门禁、计划恢复、覆盖提交／回收及受控 E2E 相关测试；真实模型夹具只做编译，不调用付费服务。无存储格式变更，不新增迁移或真实库操作。
5. 本变更沿用未归档的 `context-summarization` 能力路径；正式目录尚无该能力，因此以 ADDED 记录同名预算要求。未来归档需合并基础变更与本次要求，保留最新 8K 决定及基础能力的其他条目；本轮不改写旧规划或验收字节。

## Risks / Trade-offs

- 更早移出源码可能导致重读 → 保留批次保护；不将 Token 总节省或模型重读次数作为未经实测的承诺。
- 最新批次本身超过 8K → 保持既有软目标例外，仍由完整请求硬上限控制。
- 配置与代码版本不匹配 → 测试实际 YAML 加载及拒绝旧值；交付时说明须配套重新加载后端。
- 旧验收记录引用 12K → 新报告只声明本轮重新执行的验证，旧记录保持历史含义。

## Migration Plan

无数据库或 Redis 迁移。后续重启后端加载配套代码与配置时生效；运行中的独立字节码副本不会随源码修改而变化。回退恢复代码固定值与 YAML 为同一版本，不清空记忆。重启、提交、推送和归档不包含在本轮操作中。
