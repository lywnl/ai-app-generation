# Spec Delta

## Purpose

为应用生成会话规定压缩后的近期原文保留预算，在减少原文上下文占用时仍保护当前用户要求、完整工具批次和可靠摘要覆盖边界，并与完整模型请求的输入门禁区分计量。

## ADDED Requirements

### Requirement: 近期原文必须跨回合按 Token 保留

系统 SHALL 以 8,192 Token 作为压缩时选择近期原文的软目标，从最新消息向前选择完整消息和工具批次。当前用户原话 SHALL 独立保护，未完成批次 SHALL 不得裁剪。合法完整回合结束不得无条件折叠工具历史或立即裁剪到软目标；较早原文仅在摘要及覆盖关系可靠提交后才可回收。计划恢复资料不占原文额度，但仍计入完整请求预算。

#### Scenario: 完整回合结束但未达到压缩条件
- **WHEN** 合法回合结束，完整请求尚未达到既有压缩阈值
- **THEN** 系统 SHALL 保留合法工具原文，不得仅因结束额外发起摘要或裁剪到 8K

#### Scenario: 下一回合继续处理上一回合问题
- **WHEN** 上一回合的完整工具消息仍在近期窗口内
- **THEN** 系统 SHALL 继续保留其原文，不得在请求投影时再次折叠这些批次

#### Scenario: 最近批次恰好达到软目标
- **WHEN** 最近多个完整批次的累计估算恰好为 8,192 Token，加入更早批次将超出目标
- **THEN** 系统 SHALL 保留恰好 8,192 的完整批次，将更早完整材料作为摘要候选，当前用户原话独立保留

#### Scenario: 加入较早批次超过目标一个 Token
- **WHEN** 最近完整批次与前一批次累计为 8,193 Token
- **THEN** 系统 SHALL 整批排除较早批次，不拆分其工具调用、任何对应结果或文件内容

#### Scenario: 最新完整批次超过软目标
- **WHEN** 最新完整批次超过 8,192 Token，但与必要上下文一起仍能满足输入硬上限
- **THEN** 系统 SHALL 保留该完整批次及其后的必要说明，允许近期原文超过软目标；未完成批次同样不得裁剪

#### Scenario: 较早原文已经可靠覆盖
- **WHEN** 较早消息退出候选窗口
- **THEN** 系统 SHALL 仅在有效摘要及其覆盖关系提交后回收原文；提交失败时保留原文，不能把候选选择当作回收授权

### Requirement: 近期原文预算配置必须一致

系统 SHALL 使用一致的 8,192 Token 默认值与生产配置，并沿用固定值启动校验；其他记忆预算和 49,152／57,344／65,536 完整请求阈值 SHALL 保持。8K SHALL 不作为整个模型请求的硬上限。

#### Scenario: 使用新版默认配置启动
- **WHEN** 加载新版程序及配套配置
- **THEN** 系统 SHALL 通过预算初始化校验，近期原文目标为 8,192，其他预算仍为已确认值

#### Scenario: 混用旧值或其他未批准预算
- **WHEN** 新版程序的近期原文配置为 12,288 或其他非 8,192 值
- **THEN** 系统 SHALL 在启动校验阶段拒绝该配置，不静默沿用旧预算
