## Context

动机和范围见 [proposal.md](proposal.md)，行为依据为本变更的三个 [specs](specs/)；用户已确认仅所有者访问、失败/取消保留工作区、基于现有数据展示原因，以及不改构建存储的预览降级方案。

现状对设计的约束：

- 前端采用 Vue 3、TypeScript、Ant Design Vue、Axios 和 Vitest。`AppChatPage.vue` 已承载对话、工具卡片、输入、停止、预览编辑与终态处理，不适合再直接堆放查询调度逻辑。
- `generationSession.ts` 以应用保存浏览器内会话，并已有事件序号、请求代次、工具记录和 `outcome`；工具调用的 `done` 不是工具成功，`plan-tool/v1` 中的 `status` 也不是计划级状态。
- 计划文件状态变化不增加 `version`。`AppPlan` 包含状态和有限修订历史，没有完整偏差历史、事件时间戳或服务端运行状态。`updatePlan` 的客户端安全参数副本为空对象，不能依赖其原始 `reason` 参数，修订原因从计划查询的历史取得。
- `AppPlanStateManager.load()` 会经目录访问助手调用 `ensureSafeProjectRoot()`，存在创建目录副作用；查询必须增加独立只读路径。现有应用删除流程由 `AppDataLifecycleFence` 关门并等待已认领的访问完成。
- 预览地址固定指向工作目录 `dist/index.html`，`VueProjectBuilder` 在构建前清理旧 `dist`。页面当前使用 `v-else` 挂载 iframe，进入生成状态会销毁它，不能保留上一版已加载内容。
- 规划评审 B1 发现 `StaticResourceController` 直接拼接生成根与请求路径并返回 `FileSystemResource`，没有排除同根的计划旁车。用户已确认本期封闭此通道，见 proposal Sources。

## Goals / Non-Goals

**Goals:** 用只读服务端快照确认计划，用既有工具事件驱动更新，保持当前工具流和 P/E 的提交顺序；把页面布局、计划同步、执行记录分别放在各自边界内。

**Non-Goals:** 不复刻后端偏差检测、不在前端控制 Replan、不增加计划专用 SSE 或轮询；不提供历史产物恢复或断流重连；不修改既有模型、文件工具和构建协议。只读访问助手属于本期新增读取能力，不改变计划写入和模型回合接管逻辑。

## Decisions

### 1. 页面布局由会话终态控制，计划状态不控制预览

对应“Vue 生成期间使用全宽工作区”和“预览切换依据真实回合终态”。为 Vue 页面保留独立的布局状态：`workspace`、`preview`、`previous-preview`。该状态与 `isGenerating`、计划状态分别管理，避免失败后一结束加载便自动展示预览。

| 触发 | 页面行为 |
| --- | --- |
| 启动或恢复浏览器内活动 Vue 会话 | 切到 `workspace`，隐藏预览，保留对话和输入 DOM；未知回合模式不靠用户文字猜测 |
| `status=done` 且 `outcome=succeeded` | 沿用既有成功收口，切到 `preview` 并刷新一次；查询失败不阻止真实成功终态 |
| `status=done` 且 `outcome=answered` | 恢复原预览布局，不修改 URL、不刷新 |
| 失败、取消、超时、异常、断流 | 保留 `workspace`、最后确认计划和已有操作记录；恢复现有输入能力 |
| 用户选择查看上一版 | 有本页保留的可用 iframe 时进入 `previous-preview`，允许返回执行区 |
| 硬刷新后只有计划快照 | 显示计划但不认定正在生成；`BUILT` 可作为已有完成计划展示，不能伪造本轮成功事件或补全丢失时间线 |

桌面生成区内部采用弹性主对话区与有宽度约束的计划侧区，不增加第三列；窄屏将计划摘要和可折叠详情排在生成流上方，输入和停止按钮保持可达。预览布局保留“当前计划”折叠入口，确保恢复的计划仍可查看。沿用项目已有颜色、图标、工具卡片和滚动约定，不照搬 Demo 中的英文内部状态、固定数量、模拟按钮或“等待用户修订”文案。

只切换布局和可见性，不重复挂载一套消息列表。生成开始时退出预览编辑并清除选中元素；隐藏 iframe 的消息不再改变当前输入。HTML/MULTI_FILE 沿用现有布局分支。相较于仅用 `!isGenerating` 显示预览，此选择能区分成功、失败和只读结束。

### 2. 新增专用只读查询服务，复用既有删除栅栏

对应“当前计划只能由登录所有者查询”和“查询不得改变计划或突破文件生命周期”。在 `AppController` 增加 `/{appId}/plan` GET 映射，应用已有 `/api` 前缀后为约定地址；新增 `AppPlanQueryService` 及其实现，使用项目已有应用数据读取和登录用户服务。控制器仅接收参数、取得登录身份并包装响应。

服务先检查正数 ID、登录用户、应用存在、所有者和 Vue 类型；管理员不旁路所有者检查。通过后获取 `AppDataLifecycleFence.tryAcquireWriter(appId)` 的短期许可，再读取应用并复核所有者和类型，随后在许可内读取计划与构造 DTO，最后释放许可。这里复用已有访问计数来让删除等待，并不执行数据写入；不获取互斥的 GENERATE/DOWNLOAD 操作租约，以免实时查询与生成互斥。

删除先关门时查询返回 `OPERATION_ERROR`；查询先取得许可时可以完成完整快照，删除等待其释放。顺序固定为“权限核对 → 生命周期许可 → 再核对应用 → 计划应用锁 → 安全目录句柄”，计划锁内部不反向取得生命周期或生成租约。

错误沿用 `BaseResponse` 和 `ErrorCode`：未登录 `NOT_LOGIN_ERROR`，非所有者 `NO_AUTH_ERROR`，应用不存在 `NOT_FOUND_ERROR`，非法 ID/非 Vue `PARAMS_ERROR`，删除关门 `OPERATION_ERROR`，计划损坏或安全读取失败 `SYSTEM_ERROR`，客户端只收到通用可读说明。响应设置 `Cache-Control: no-store`；不在服务端或浏览器持久化计划查询缓存。

返回 `AppPlanVO`，字段固定为 `planId`、`version`、`status`、`summary`、`files`、`history`；文件项包含 `path/purpose/action/dependsOn/state`，历史项仅含 `version/reason`，按现有顺序返回最多已有的 20 条记录。不返回活动回合令牌、原始反馈、完整历史差异或编造的时间戳。合法无计划返回成功且 `data: null`。用户字符串按文本呈现，不作为 HTML 执行。采用受限 DTO 而非直接返回 `AppPlan`，避免把内部字段固定成公共接口。

### 3. 为查询增加无副作用的安全读取入口

新增 `AppPlanStateManager.loadReadOnly(appId)`，复用现有应用锁、计划对象和依赖合法性校验；新增 `PlanStoragePathResolver` 的只读目录访问方法。现有 `load/loadForTurn/save` 及写入路径保持原行为，新接口禁止调用它们创建目录或绑定回合。

只读访问从配置的生成根建立不跟随符号链接的目录句柄链，打开指定项目及 `.plan.json` 时使用 `NOFOLLOW_LINKS`，文件只以 `READ` 打开。路径段不得先检查后再用不受保护的绝对路径重新打开。根/项目目录或计划文件确实不存在返回空；符号链接、非普通文件、无权限、不支持安全目录句柄和 JSON/计划语义损坏返回读取失败，不自动修复、不回退到普通路径访问。

在同一应用锁和安全句柄内读取一份完整 JSON 并映射为 DTO，缺失与不安全路径必须分别处理。此方案比简单在 `load()` 外层加 `Files.exists` 更可靠，因为后者既不能消除目录创建，也不能保护检查后到打开前的路径替换。

### 4. 查询快照与工具事实分工，避免前端维护第二份计划真源

对应“计划展示区分持久状态与执行提示”和“现有工具事件驱动计划查询与执行记录”。新增类型及解析工具 `planSnapshot.ts` 和查询封装 `api/appPlan.ts`，使用现有 Axios 实例。新增 `useGenerationPlan` 组合函数持有 `snapshot` 与 `idle/loading/ready/empty/stale/error` 同步状态，并管理查询生命周期。

`generationSession.ts` 只增加供订阅者使用的当前本地回合标识和计划相关事件修订计数，不承担 HTTP 查询。计数仅在合法、首次接收的相关 `tool_executed` 和终态变化时推进；相同工具 ID 的重复结果不重复增加记录或计数。相关工具为 `makePlan/updatePlan/writeFile/modifyFile/deleteFile/readFile/readDir/buildProject`，包括失败和拒绝结果，因为它们也可能触发计划偏差。工具参数增量和普通文字不会触发查询。

面板中的文件清单、进度、计划级状态和历史只接受查询快照；SSE 负责立即展示正在调用哪个工具、该次操作的可信结果及待同步提示。成功变更发生但查询尚未完成时可显示“该操作已成功，计划同步中”，不先推断全部文件已完成或计划就绪。`makePlan/updatePlan` 的结构化结果用于工具记录，完整当前计划随后由查询确认。

DTO 解析检查结构、枚举、相对路径与依赖引用；读取不到可识别 DTO 时仅将面板标为查询异常，不能关闭生成 SSE。前端不复制依赖重置、失败次数或 fail-open 判定。若计划事件没有精确覆盖服务端状态变化，本期只在下次相关事件或手动重试时核对，不承诺所有瞬时状态可见。

### 5. 查询串行合并并丢弃过期响应

`useGenerationPlan` 以“登录用户 ID、应用 ID、本地回合标识”为上下文，维护递增的本地观察序号和查询编号。首次进入、恢复已有浏览器会话、新回合启动、相关工具完成及最终收口均触发核对；订阅初始快照与页面首次加载的重复触发合并。

同一上下文最多一个请求在途。新事件到来时标记已有快照待同步并提升观察序号；在途请求完成后，若期间有新事件，则丢弃该响应并立即发起一次合并查询。只有上下文、查询编号和观察序号仍匹配时才替换快照，不比较 `version` 的大小来决定新旧。这样能处理同版本进度、修订回退和连续文件变更；高频事件期间保留上次确认值及同步标识，最后一次事件后核对最终状态。

查询使用可取消请求和 10 秒超时。网络或服务器错误显示重试入口，保留但标旧快照；不自动定时重试。若失败期间有新的待处理事件，仍执行那一次合并查询。权限或应用不存在错误清空快照并停止查询，等待合法上下文重新建立。计划查询失败不会改写生成的真实 outcome。

路由、登录用户或本地回合改变时提升上下文代次，取消旧查询并拒绝其晚到回调；旧 SSE 会话不写入新面板。页面卸载取消查询而不额外取消既有后台生成；重新进入后订阅当前会话并重新查询。终态处理先保留页面需要的最终工具记录与本地回合标识，再调用既有 `clearGenerationSession`，最终查询由组合函数完成，不会随 SSE 缓存清理而丢失。所有新增计划缓存仅存在内存，不写 localStorage。

采用事件触发合并查询，而不选择轮询或新增 SSE：符合本期已确认协议边界；相较于用 `version` 丢弃响应，它能处理文件状态不升级版本的实际实现。查询快照可以比浏览器已收到的工具事件更先进，它展示的是当前计划，而不是精确重放每个事件时点。

### 6. 展示组件只消费视图模型

新增 `GenerationPlanPanel.vue` 展示目标、版本、中文状态、进度、文件动作/用途/依赖、已有修订记录和同步异常；新增 `GenerationExecutionTimeline.vue` 从已有工具记录生成紧凑摘要，点击可定位现有工具卡片，不复制源码预览。组件不发模型请求、不改计划，HTTP 与排序放在组合函数中，避免扩大 `AppChatPage` 主流程。

文件进度分母为计划内非 `KEEP` 条目，分子为这些条目中的 `TOUCHED` 数量；`OUT_OF_PLAN` 单列，`KEEP` 显示“无需变更”。分母为零显示“无需文件变更”，不显示通过构建。依赖等待按当前快照判断直接依赖是否为 `KEEP` 或 `TOUCHED`，只是说明，不据此阻止工具。执行中提示来自当前会话未完成工具及其已取得的合法相对路径；没有路径不关联文件。

计划级中文映射为 `PLANNED`“计划执行中”、`REPLAN_PENDING`“计划待调整”、`READY_TO_BUILD`“待构建”、`BUILT`“已构建”。没有活动会话时 `PLANNED` 改显示“计划未完成”，避免假装模型仍在运行。文件 `TOUCHED` 显示“已变更”，不能叫“验证通过”。

偏差说明优先展示当前记录中可核验的计划外路径或未满足依赖；具体工具失败仅作为该次操作的事实，不直接宣称为 Replan 根因。无法确定关联时使用“计划待调整”的通用提示。修订原因从同一计划查询的 `history` 获取，并明确属于已发生修订，不当作当前偏差原因。失败消息用现有标准化展示规则，不透传内部指令、原始参数或服务端堆栈；不通过解析 AI Markdown 提取状态。时间线只显示本会话已收到的事实，不补造服务端时间或刷新前事件。

### 7. 保留已加载 iframe，明确上一版不是版本快照

对应用户新确认及“上一版预览无法恢复”场景。Vue 预览容器通过 `v-show` 或等价 CSS 隐藏，iframe 的存在不再由 `isGenerating` 分支销毁；回合开始不改 `src/key`，保留已加载的 DOM。只有本轮成功收口才沿用 `updatePreview(true)` 切换结果，只读结束原样显示。

页面记录当前 iframe 是否已加载、是否在本轮开始前保留，以及该次加载身份。失败后主动查看上一版只展示本页已保留内容，标题标为“上一版预览”，不另开同一个静态 URL 冒充历史版。若本页没有保留内容、发生导航或硬刷新，上一版区域显示“上一版预览暂不可用”，不从浏览器缓存、URL 时间戳或计划 `BUILT` 推导历史版本。

iframe 的 `load` 不是网站健康证明。对可访问的同源 iframe 观察资源加载错误；收到明确加载错误、检测到错误文档或加载超时即标不可用，跨源无法核验时不宣称资源完整。本页保留的内容也可能因延迟加载资源失效；提供返回执行区，提示保留内容不等于可恢复构建产物。新一轮开始后晚到的旧加载回调必须按 iframe 加载身份拒绝，不得触发成功状态或恢复编辑模式。此调整只涉及预览生命周期，不新增静态资源协议或产物存储。

### 8. 静态入口封闭计划旁车读取，不改变网站公开预览

对应查询规格新增“静态资源不得提供计划旁车文件”，以及用户批准的 B1 修订。保留现有 `/static/{deployKey}/**` URL 和公开访问，新增专用 `StaticPreviewResourceResolver` 承担路径解析与安全读取；不直接复用 `ProjectPathResolver.isProtectedPath`，因为其中禁止 `dist`，会破坏 Vue 正常预览。

请求 URI 从 Servlet 提供的原始路径按 context 与固定映射边界拆分，使用严格 UTF-8 按路径段解码一次；不用表单解码把 `+` 变为空格，也不将原始字符串拼入文件路径。`deployKey` 必须是单个目录段，解码后的段禁止点段、反斜杠、控制字符、嵌入分隔符及残留可再次解码的百分号转义。比较 Spring 路由中的 deployKey 与解码目录段的一致性；歧义路径直接拒绝，不继续尝试多次解码。普通中文、空格和合法资源文件名按一次编码访问。

对解码后的每个段按不区分大小写的保留名称匹配 `.plan.json`、`.plan-*.tmp`，再确认解析结果位于所选应用目录内，防止大小写不敏感文件系统和跨目录绕过。静态入口对这些文件一律 404，即使用户是所有者也不例外；非法编码等由容器提前返回 4xx 可以保留，但不允许任何分支返回计划字节或内部路径。普通目录根重定向和默认首页也须在目录名校验后进行。

从可信生成根的目录访问边界，以安全目录句柄逐段打开应用目录和资源父目录，全部使用不跟随符号链接的读取方式，只接受普通文件；路径解析器不得创建目录或自动修复链接。无法建立安全边界时拒绝而不是回退绝对路径。拒绝文件和父目录链接，包括从普通文件名指向计划的别名。

不能只在 Controller 中检查一次后返回会再次按绝对路径打开的 `FileSystemResource`。新增受限 Resource 实现，由其 `getInputStream()` 在响应写出时重新经过同一安全路径解析和句柄打开，读取已经打开的文件通道；预检查及元数据访问也通过该解析器。流关闭时释放通道，HEAD 不保留未消费的打开流；容器处理中断时不泄漏句柄。这样即使预检查后文件被替换为链接，实际读取仍无法跟随。保持原有正常资源响应类型、内容类型映射、缓存策略、默认首页和根重定向，不新增构建存储或版本路由。

验证使用隔离目录和真实 Controller/资源读取链：除了断言返回状态，还消费实际响应体，确保没有仅 Mock 掉资源打开而漏掉延迟读取旁路。涵盖直接计划、写入临时文件、编码变体、点段、跨应用路径、文件/父目录链接及预检查后替换；使用 GET/HEAD 覆盖正常资源与拒绝路径。此方案比单纯原始 URL 黑名单稍多一个读取组件，但能封闭 B1，同时不把公开网页改成所有者专用页面。

## Risks / Trade-offs

- **[瞬时偏差可能不可见]** 现有工具事件先后与偏差写回不完全重合 → 事件触发查询与最终核对，未知原因使用通用提示；不修改 Replan 主链路来满足监控完整性。
- **[查询占用文件读取]** 每次相关工具结果增加一次核对需求 → 单请求串行合并、无轮询，应用锁只包住单次读取与校验，不在锁内等待网络。
- **[旧结果覆盖与跨账号泄漏]** 计划版本不是进度序号 → 使用本地上下文代次和观察序号；权限丢失立即清空，不使用共享持久缓存。
- **[部署多实例限制]** 当前锁、删除栅栏和文件系统能力沿用单实例本地目录假设 → 本期不宣称分布式一致性，若部署拓扑改变需另行评估。
- **[安全读取差异]** 旧读取路径可能创建目录或将链接视为空计划 → 新只读路径明确区分不存在与错误，补充路径替换和文件类型测试，不修改旧工具写入语义。
- **[预览不能恢复历史]** 旧 `dist` 会被清理或覆盖 → 遵循已确认 A，只保留本页已加载内容；刷新和资源失效可降级，不承诺所有浏览器、跨源或延迟资源均能保留。
- **[静态旁路与兼容]** 只保护新接口或只检查原始路径不足以保护原计划 → 解码边界与实际文件打开共同检查，新增 GET/HEAD、链接替换及正常 dist 资源回归；不扩大为整个网站登录鉴权。

## Validation Strategy

- 后端聚焦验证所有者/未登录/跨用户/管理员、应用类型、空计划、损坏计划、符号链接、查询无目录创建、原子替换、删除先到与查询先到；断言无模型调用、无回合重绑定、无文件内容变化及无内部字段泄漏。
- 静态资源测试消费真实临时文件响应体，验证所有身份下原计划与临时文件不可获取，编码/越界/链接及延迟打开不能绕过，正常匿名 HTML/JS/CSS/图片/字体、根重定向、默认首页和 HEAD 行为不回归。
- 前端使用 Vitest 控制 Promise 完成顺序，覆盖同版本进度、连续事件合并、旧响应、账号/应用/回合切换、最终查询、权限丢失、查询失败不终止 SSE 和重复工具结果；单独验证计划状态与调用状态映射。
- 回归既有 P/E、文件协议、构建门禁、SSE、工具卡片与滚动测试；执行 `bash mvnw -Dtest=<相关测试> test`、前端 `npm run test -- <相关测试>` 及 `npm run build`，具体测试集合在 tasks 登记。
- 浏览器以可控接口/SSE 样例验证桌面和移动端：生成隐藏预览但保留 iframe、成功才刷新、只读不刷新、失败/取消仍可输入、上一版可用与失效提示、进入/离开页面、编辑退出和现有工具卡片状态。截图和原始日志放项目 `.codex/`；本期模拟验证不等于真实模型端到端验收，真实服务调用遵循既有授权。

## Migration Plan

1. 先将静态旁路防护与只读后端接口作为同一个后端交付单元发布，再发布前端工作区；不能只发布新权限接口而遗留已知静态旁路。后端上线前前端查询失败只能影响计划面板，不能破坏旧生成流。
2. 不迁移 `.plan.json`、数据库或聊天记录，不执行后台回填；无计划应用显示空态，不因用户打开页面自动创建计划。
3. 回退时先回退前端工作区，再按需撤下只读接口；静态计划文件防护独立保留，不因前端回退重新开放原始计划。既有计划写入、工具事件和构建存储始终保持原契约。发布操作需另行取得对应授权。
