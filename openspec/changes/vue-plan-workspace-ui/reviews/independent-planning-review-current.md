## 实施验收提醒

以下是现任务要求的落实点，不构成新的需求阻塞：

1. 受限 Resource 的 `contentLength`、`lastModified`、`getInputStream` 等访问都必须保持同一安全解析策略，不能某个辅助方法退回绝对路径。需要以实际消息转换器消费资源验证 GET、HEAD、关闭和写出异常，而非只断言 Controller 返回的 Resource 类型。
2. 预检查与实际打开之间资源失效时必须保证不返回计划字节；响应已经开始后的 I/O 失败不能承诺还能改写状态码，不应因此退回不安全读取。直接受保护路径则按规格在返回资源前拒绝。
3. 原报告中的页面提醒仍适用：处理 `fetchAppInfo` 消息数触发的预览初始化，避免硬刷新把当前固定静态地址当成上一版；新增结果观察去重不改写 SSE 协议校验。现有任务 3.2、6.2、6.4、7.3 已覆盖验证位置。
