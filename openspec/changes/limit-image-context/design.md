# Design

## Context

动机见 [proposal.md](proposal.md)。当前调用链为规划服务 → 并发图片工具 → `ImageCollectionPromptBuilder`；在线入口使用 `collectPromptContext`，兼容入口使用 `enhancePrompt`，二者共用收集过程。`ImageSearchTool` 使用 Hutool HTTP，项目已有 JUnit/Mockito 和本机 HTTP 替身测试。

## Goals / Non-Goals

统一三个收集边界的上限，不依赖规划模型或图片提供方自觉遵守。保留现有类型、构造服务依赖和并发调度方式；不引入缓存、额外模型调用或配置系统。范围边界及执行授权见 U2。

## Decisions

### 1. 共享无状态策略

新增内部 `ImageCollectionPolicy`，集中 6／3／18／1／80 常量与纯筛选函数。关键词归一 Unicode 空白，按 `Locale.ROOT` 忽略大小写去重，保留第一次出现的规范化关键词；Logo 只判定是否有效，完整描述不裁剪。

去重集合均为调用内局部变量。资源筛选按类别配额、有效 URL 和输入顺序选择，以复制对象承载清理过首尾空白的 URL，不更改输入对象。语义近似主题仅由提示词引导合并；不使用模糊去重，避免错误合并用户需要的不同内容。

### 2. 请求前限制与响应侧限制

`ImageCollectionService` 在提交线程池前选择任务，保留 Logo 先提交。`ImageSearchTool` 以 `per_page=3&page=1` 发出请求，解析时跳过无效数据与重复 URL，满足 3 张即停止收集。服务对每个工具结果再次执行类别和配额限制，再对汇总结果统一去重及限制。

仅修改请求参数不足以防止提供方超量；仅裁剪文本不能减少已发生的请求，所以两处都限制。服务级兜底同时覆盖测试替身和未来工具实现。保留超时、取消、等待窗口及 MDC 代码，日志记录原始与有效任务数和最终图片数，不记录整份提示词、密钥或素材清单。

### 3. 最终文本入口兜底

`ImageCollectionPromptBuilder` 对直接调用同样执行 18／1 限额和 URL 去重；描述清理空白后，超过 80 个码点时保留前 79 个并加 `…`。短描述保持清理后的内容，空描述输出空文本。URL 只清理首尾空白，保留全部路径、参数和编码。

这使 Logo 的生成设计和最终素材说明分离，避免压缩生成需求。保留当前素材标题、分类名称与每行“分类：说明（URL）”格式。

### 4. 提示词与协议

只修改现有图片规划系统提示词，明确规格中的主题和配额原则。`ImageCollectionPlan` 的两个数组与 `query`／`description` 字段不变；公共 API、图片资料持有与回收位置均不变。

### 5. 本地验证

搜索工具保留生产无参构造，增加包内 endpoint 构造入口供本机随机端口 HTTP 替身使用，无新增生产配置。验证真实 Hutool 请求参数、超量／畸形／错误响应以及实际 service → search → builder 组合链路；规划和 Logo 使用替身，真实外部调用次数为零。

复用现有 Maven 离线配置与图片、Logo 轮询及 Facade 测试。原始证据放 `.codex/limit-image-context/`，结构化映射放变更 `reports/`。standard 在当前执行上下文自查，不宣称独立审查或生产验收。

## Risks / Trade-offs

- 候选更少可能降低素材多样性 → 按主题首现顺序选择，不补搜凑数，保留完整 URL 供页面使用。
- 参数不同的 URL 可能仍指向同一图片 → 按完整 URL 判等，避免移除签名或变换参数导致地址不可用。
- 数量和描述长度不能给出固定 Token 预算 → 不限制 URL 长度，不承诺固定节省比例。
- 并发和 Logo 取消容易被重构误伤 → 限制修改于调度前及结果筛选，复用既有并发／取消回归。

## Migration Plan

无数据迁移。源码编译测试后交付；运行中的后端需要后续按用户要求重启才加载新版本。回退本轮代码和提示词即可恢复旧行为，保持现有资料和存储内容不变。
