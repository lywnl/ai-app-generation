1. facade 使用动态 `context::requiresBuild`；初始 `READ_ONLY` 枚举保留。只有文件工具受信 `APPLIED + changed=true` 结果进入升级路径，旧构造入口仍兼容。

3. 初始化统一先取得租约提交锁再检查回合就绪位，未引入 context-monitor 与 lease 的反向获取。完整装配后才置就绪，不重复重置 Replan 计数；无计划仍完成检测器装配。
4. 结果提交成功后才安排升级反馈、观察可信进展或认领初始化失败终止。同批剩余工具沿既有受控跳过路径补齐结果，不执行真实构建。文件协议、计划协议、SSE 字段均未增加。
5. 升级反馈读取最新计划，读取租约时不占用控制器 monitor。普通、协议恢复、未完成工具链恢复三条路径均加入反馈；只有实际消息中包含反馈时绑定请求代次，再由当前有效回调确认送达。未携带、准备失败、启动无回调失败、取消后的迟到回调均不消费送达状态。
6. 首次修改后重新读取有效权限，可信进展能进入既有保护器；`before=null` 不会将回合绑定本身误计为减少阻塞。计划 KEEP/PENDING 规则未放宽。
