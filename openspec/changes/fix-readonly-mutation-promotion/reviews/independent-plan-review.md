## 实施核验重点

以下是现有设计下的实现约束，无需扩大需求或阻塞规划：

1. 初始化所有入口统一先取得活动 lease 边界再检查就绪；避免正常初始化先锁 context、升级时先锁 lease 产生反向锁序。完整装配成功后才能置就绪，下一回合不复用该状态。
2. 初始化失败后必须跳过可能再次读取故障计划的进展诊断，避免二次异常覆盖真实 APPLIED 结果；结果提交失败、取消先赢时不得再发升级反馈或启动请求。
3. 只在实际请求消息包含对应升级反馈时绑定目标代次；SDK 同步有效回调可确认送达，仅准备请求或启动失败不可确认。不能单纯复用构建票据的非空判断而漏掉独立升级反馈。
4. 保留 `FileToolScope`、`GuardedToolExecution` 既有构造入口。内部终止枚举需同步全部终态 switch、转录映射和固定文本预算，仍使用 SYSTEM_ERROR、refreshPreview=false，且同批剩余真实工具不可执行。
5. 以真实文件工具、隔离文件系统和受控模型覆盖初始 READ_ONLY 到成功构建的完整链路，并覆盖初始化失败、取消竞争、同批工具和恢复；单独布尔值测试不构成完成。
