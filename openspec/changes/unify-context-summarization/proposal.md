# Proposal

## Why

当前 L1 只处理已完成用户回合，长工具链另用执行清单检查点；正常回合结束后的整轮折叠和请求投影还会提前移除近期原文，使具体报错、尝试过程与决策理由难以跨回合延续。此次统一历史与当前工具批次的摘要和保留规则，并让每次模型请求看到最新计划，在保留可信工程结果的同时改善任务连续性。

## What Changes

- 使用一套压缩流程和一份 L1 会话滚动摘要，合并尚未覆盖的历史消息、决策证据及当前已完成工具批次；移除本轮检查点文本投影与专用重建分支，失败时保留上一个有效快照。
- 按 12,288 Token 软目标选择跨回合近期原文，保护当前用户原话和完整工具配对；用摘要后的完整请求判断后续压缩，沿用 D1 的摘要上限、三段门禁和截止时间，不因回合结束额外调用摘要模型。
- 保留并精简可信结果生成与持久化，取消合法完整回合的无条件整轮折叠；请求层保留窗口内工具消息，已被 L1 覆盖的旧结果不再逐轮额外注入，必要的当前工程状态仍由后端提供。
- 每次 Vue 在线模型请求读取最新已提交计划，包括只读问答、工具续调和现有恢复请求；同版本内状态变化也须反映，每次只注入一份，不重复初始化或绑定回合。
- 独立保存有来源的用户决策、否决原因和已执行模型方案理由，覆盖未触发压缩的短回合；在统一摘要中提炼，区分实施与验证，不混入可信结果字段，不新增独立决策模型调用或决策工具。
- 扩展摘要覆盖边界和修订元数据的原子持久化，兼容旧摘要、旧已折叠历史和现有冷重建；请求读取同时校验 L1 与 L0 的相容性，发生裁剪交错时在原截止内整对重读或受控失败；取消、删除接管、源变化及过期提交不得推进失效状态。

### Non-Goals

- 不改变 RAG、图片和 Skill 目录的既有准备与注入规则，不增加资料自动淘汰、资源库、跨回合资源缓存或回读工具；运行反馈继续遵守原送达机制。
- 不重做 L2，不增加任务自动续跑或全量工具事件数据库持久化，不承诺冷启动还原尚未摘要的完整工具轨迹。
- 不删除可信工程结果，不改变真实构建、只读升级、取消、超时、删除接管及异常工具链的现有约定；保持 HTML、多文件生成兼容，独立评估链不接入生产持久记忆。

## Capabilities

### New Capabilities

- `context-summarization`: 单份会话滚动摘要、完整工具批次保留、跨回合近期原文、完整请求预算、摘要覆盖与失败处理，以及可信结果在上下文中的保留和去重。承接 D1 的 FR-01、FR-02、FR-06 和持久化兼容要求。
- `conversation-decision-evidence`: 决策证据的来源、实施与验证状态、独立留存及摘要使用规则，确保短回合也有可追溯材料，并隔离模型解释与可信事实。承接 D1 的 FR-05。

### Modified Capabilities

- `vue-soft-replan`: 扩展“在线变更回合必须维护结构化计划”及其计划注入场景，从回合开始时的计划说明升级为每次模型请求读取最新快照，明确只读读取与一次性回合绑定的区别；更新“软 Replan 不得改变非目标模式和现有终态协议”中的记忆职责边界，使本次记忆变化由 `context-summarization` 约束，保留其余非目标模式、工具与终态兼容要求。

`vue-build-progress-guard` 和 `vue-mutation-promotion` 的需求保持不变，作为本次兼容约束与回归依据，不另建重复能力。

## Impact

- **记忆与执行链路**：影响 L1 输入与覆盖计算、近期窗口选择、正常回合收尾、可信结果请求投影和冷重建；最新计划读取接入现有模型请求准备及 Token 门禁。源码参考沿用来源登记 C1～C5，具体接口与消息适配在 design 中确定。
- **持久化与兼容**：MySQL 摘要记录增加覆盖与修订元数据，聊天记录增加可空的独立决策证据；Redis 中合法完整回合的原文由统一摘要管理退出时机。迁移保留旧数据，不补造历史工具轨迹或决策理由；对外聊天 API 和工具协议保持兼容，不引入新框架或服务。
- **成本与风险**：当前长工具链可触发语义摘要，增加相应摘要模型工作量；通过增量合并、复用和既定预算控制，不新增每回合结束的固定摘要调用。维持元数据中的 `strict` 等级，重点关注持久化原子性、消息覆盖错位和可信事实边界。
- **验证范围**：沿用 D1 第五部分，重点覆盖连续三次压缩、跨回合 L0 与实际请求均保留近期原文、旧结果不重复注入、同版本计划刷新、短回合决策证据、失败与迟到回调、旧数据和冷重建。构建保护及修改升级使用现有规范回归，不以文档状态代替实现验收。
