# Spec Delta

## Purpose

使 Vue 在线生成能在每个用户回合按实际修改需求补充功能与图片资料，同时控制外部调用、等待时间及上下文占用；保留可靠的只读边界、首次成功语义和取消隔离，避免候选清单跨回合累积。

## ADDED Requirements

### Requirement: 每个用户回合联合判断模式和资料需求
系统 SHALL 对本轮原始用户消息进行一次联合判断，取得 mode、needRag、needImageSearch；模式仅允许 READ_ONLY 或 MUTATION_REQUIRED。系统 MUST 保留纯问答只读、含修改或构建意图为修改、混合意图为修改以及模糊意图按修改的既有规则，不因资料关键词本身判定修改。历史、摘要和旧计划不得参与本次分类。

#### Scenario: 图片关键词的纯问答
- **WHEN** 用户询问“这些图片来自哪里，请解释，不要修改”
- **THEN** 模式为 READ_ONLY，图片和 RAG 标记均归一为 false，不准备也不注入候选资料

#### Scenario: 模式与资源字段分开校验
- **WHEN** 响应为完整 JSON 对象且 mode 合法，但某个资源字段缺失、为 null 或类型错误
- **THEN** 仅对应资源字段降级为 false，并记录固定降级原因，不再次调用模型修补

#### Scenario: 无可靠模式
- **WHEN** 普通请求模型调用失败、响应不是完整 JSON 对象或 mode 缺失或非法
- **THEN** 前置失败，不从自然语言猜测模式；保留真实异常原因和既有安全余额提示，不展示原始模型响应

#### Scenario: 非授权字段
- **WHEN** 模型额外返回 needLogoGeneration 或其他字段
- **THEN** 额外字段不能控制资料准备，其他工程类型路由仍保留其枚举协议

### Requirement: 选中元素请求固定修改并判断资源
系统 SHALL 保留选中元素请求的服务端固定修改模式，并调用一次联合模型获取资源需求。模型不能将其降为只读；调用或完整解析失败仅将两个资源标记降为 false，之后仍应用首次强制策略。

#### Scenario: 模型与固定模式冲突
- **WHEN** 选中元素请求的模型输出合法 READ_ONLY 和 needImageSearch=true
- **THEN** 服务端先固定 MUTATION_REQUIRED，保留合法资源需求，再执行最终资源策略

#### Scenario: 选中元素分类失败
- **WHEN** 模型调用失败或输出损坏 JSON
- **THEN** 继续固定修改模式；无成功终态时仍强制准备两类资料，有成功终态时不准备资料

### Requirement: 首次资格来自持久化成功终态
系统 MUST 仅用本应用未删除的 ai 历史中 memoryOutcome=SUCCEEDED 的存在性判断首次资格，不加载聊天正文。只读、失败、取消、超时、系统错误及无可靠成功标记的旧记录均不算成功；查询失败必须前置报错，不猜测。该判定不得新增存储字段或修改旧记录。

#### Scenario: 首次失败后重试
- **WHEN** 应用只存在只读、失败或取消记录，当前为修改请求
- **THEN** 即使目录或部分文件已存在，仍按首次成功前的强制准备策略处理，但不得以此授权重建既有工程

#### Scenario: 重启或跨应用
- **WHEN** 一个应用已持久化 SUCCEEDED，另一个应用没有，或服务重新启动
- **THEN** 分别按本应用的可靠记录选择后续或初始策略，不受 JVM 缓存或另一应用影响

### Requirement: 服务端固定本轮召回策略
系统 SHALL 在回合开始固定最终策略：只读不召回；修改且尚无成功终态强制两类资料；成功后分别按资源标记召回。RAG 总开关仍生效。工具续调、压缩、协议恢复及只读真实修改升级不得重新判断资源或重新召回。

#### Scenario: 成功后的多种修改
- **WHEN** 成功后依次进行样式调整、新增新闻功能、更换背景图，资源标记分别为 false/false、true/false、false/true
- **THEN** 三轮分别准备无资料、仅 RAG、仅图片，各自独立生成本轮候选

### Requirement: 初始和后续 RAG 保持工程兼容
系统 SHALL 在首次成功前使用初始化需求和不同的本轮要求召回骨架及最多 4 个兼容功能片段；成功后聚焦本轮要求，仅查询功能片段池，最多交付 2 个片段。后续按当前工程实际依赖验证兼容、按目录版本及文档 ID 去重，不查询或重排骨架池，不授权改变既有技术栈。

#### Scenario: 后续资料专用语义
- **WHEN** 后续功能召回成功或为空
- **THEN** 仅交付有效功能参考，空结果不产生“缺少骨架，创建最小工程”的提示；保留原功能分区预算和原子文件裁剪

#### Scenario: 无法安全确认兼容
- **WHEN** 当前工程 package.json 缺失、超过 64 KiB、损坏、路径不安全或依赖兼容性无法确认
- **THEN** 不注入无法验证的功能模板并记录降级，不重建工程

#### Scenario: 检索渠道失败
- **WHEN** 向量、BM25 或重排部分失败
- **THEN** 沿用可用渠道及 RRF 降级，截止后不再启动后续检索或重排，全部不可用时无功能模板

### Requirement: 图片配额按阶段贯穿请求和交付
系统 SHALL 首次成功前最多搜索 6 个主题、成功后最多 2 个主题，每主题最多 3 张，Logo 单独最多 1 张。配额在外部请求之前与最终交付之前均执行；主题与 URL 调用内去重，描述最多 80 个 Unicode 码点，URL 完整，空任务不查询、不为凑数补请求。

#### Scenario: 后续超量图片规划
- **WHEN** 后续图片规划返回多个重复或空白主题及超过限额的有效主题
- **THEN** 归一去重后最多请求 2 个主题，提供方超量返回仍最多交付 6 张搜索图和 1 张 Logo

#### Scenario: Logo 与背景需求
- **WHEN** 成功后准备图片资料
- **THEN** 图片规划以本轮要求为主、受限初始化需求为背景，默认沿用 Logo，仅当前需求要求新建或更换时生成；首次强制准备不强制非空结果或 Logo

### Requirement: 所有资料准备共享单一截止时间
系统 MUST 在保存原始用户消息后开始资料准备时建立单调时钟截止：初始 15 秒、后续 8 秒，且不超过剩余回合期限。预算覆盖兼容读取、排队、请求许可、检索、重排、图片规划、搜索、Logo 提交轮询和汇总；不包括联合分类与主生成模型。两类资料并行，保持现有有界执行器和接纳限制。

#### Scenario: 截止时部分交付
- **WHEN** 前面的任务慢而后面的任务已在截止前完成
- **THEN** 收集所有已完成有效结果，按原任务顺序交付，不因依次等待遗漏结果；资料超时可继续主生成

#### Scenario: 排队和迟到任务
- **WHEN** 任务在队列等待耗尽预算或执行结果在截止后返回
- **THEN** 不发起新的外部调用、不接纳迟到结果，取消未完成任务并清理排队项；不重置每个子任务的预算、不修改共享客户端全局超时

### Requirement: 取消和删除切断资料与主生成
系统 MUST 将资料任务登记为独立可注销的通用租约取消回调，不占用主生成模型取消位置。用户暂停或应用删除后不得创建主生成流、发起新的资料子任务或注入迟到结果；资料任务结束必须清理回调及队列。

#### Scenario: 准备期间用户取消
- **WHEN** 图片规划或 RAG 尚未完成时用户取消或删除应用
- **THEN** 取消相关任务，拒绝迟到回调和主模型启动，保留既有回合终态与删除协议

### Requirement: 候选资料仅在本轮冻结复用
系统 SHALL 每个新用户回合创建不可变的 RAG 与图片参考资料列表，本轮清单替代上轮候选，不累积、不回填旧结果。未召回、失败或为空的类别不得注入上一轮候选。临时资料不作为独立来源进入 L0/L1 或数据库；已采用代码、URL、工具批次和决策继续按既有规则保存。

#### Scenario: 本轮续调与下轮覆盖
- **WHEN** 一轮内发生工具续调、同步压缩或协议恢复，随后进入另一用户回合
- **THEN** 同轮使用同一份固定资料且不重复检索，下一轮使用新列表；候选替换本身不删除已生成文件或已采用 URL

#### Scenario: 计量与发送一致
- **WHEN** 资料被附加到主模型请求
- **THEN** 完整请求按同一冻结快照计量和发送，资料 Token 计入本地预算，工具调用与结果保持完整批次

### Requirement: 可审查的评测和运行观测
系统 SHALL 记录应用及回合标识、路由与策略、固定降级原因、资料阶段耗时和数量、完成状态及本地预算 Token，不记录密钥、完整用户需求或原始模型响应。验收必须包含真实 Java 链路替身测试，以及另行授权的 60 条合成输入旧新各两轮、最多 240 次真实分类对照。

#### Scenario: 分类效果判定
- **WHEN** 同版本同采样参数完成真实分类对照
- **THEN** 分别比较两类误判、非法输出和耗时，新版两类误判均不得增加、关键明确不修改样例不得新增误判；资源准确性单独统计，未运行不能宣称无退化
