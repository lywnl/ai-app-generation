# Design

## Context

问题与范围见 proposal。后端 Java 25 / Spring Boot / MyBatis-Flex；前端 Vue 3 / TypeScript / Ant Design Vue / Vitest。历史接口返回 `Page<ChatHistory>`，`decisionEvidence` 已 `JsonIgnore`，但 `memoryMessage` 和 `memoryOutcome` 尚不是展示隔离字段。部署服务在构建及复制成功后同时持久化 `deployKey` 与 `deployedTime`，AppVO 提供由服务端构造的 `deployUrl`。

## Goals / Non-Goals

以现有接口和字段满足 `app-conversation-view`，不增数据库、依赖或公开检索列表。普通非作者页面只提供发布预览；管理员原有管理权限与作者工作区继续有效。不改变静态资源接口原有公开策略，不新增撤回部署或分享开关，不扩展计划与记忆查看功能。

## Decisions

### 服务端以精选状态和部署完成记录联合授权

`listAppChatHistoryByPage` 先校验应用 ID、分页和有效登录用户，再读取当前 App。作者或管理员保持可读；其他用户需要 `AppConstant.GOOD_APP_PRIORITY.equals(priority)`（99）、非空白 `deployKey` 和 `deployedTime != null` 同时成立，不信任 URL 的 `view=1`。逻辑删除／不存在仍返回 NOT_FOUND；每页重新检查精选及部署资格，取消精选后的下一页被拒绝，不缓存权限。

部署状态选择两个现有持久化字段，是因为它们在部署成功后一起保存；再结合当前精选值满足 U3。封面、目录、构建成功或单一字段均不能代替三个条件。不新增在线文件存在性检查，临时发布资源故障不撤销历史读取能力。

### 共享历史采用展示字段白名单

保留 `Page<ChatHistory>` 及作者／管理员响应兼容性。普通非作者的返回记录复制为展示对象，仅包含 id、message、messageType、appId、userId、createTime、updateTime；不把 memoryMessage、memoryOutcome、decisionEvidence 和持久化内部标记复制到响应。复制不修改数据库实体、L0/L1/L2 或原始记录。用 HTTP 序列化测试验证内部值没有出现在响应中，不仅验证 Java getter。

不全局增加 JsonIgnore，避免改变原有作者／管理入口；不为一条查询引入独立分享接口或权限框架。

### 页面按身份拆分初始化

从已加载 AppVO 和登录用户计算作者身份，缺失 ID 不得因 undefined 相等被视为作者。把身份和非作者预览 URL 的选择放入可单测的 `appViewAccess.ts`，后端仍是最终权限裁决。

普通非作者在 AppVO 到达后，先检查精选与部署资格，再独立加载 deployUrl；条件不满足时不加载 iframe，并明确提示仅精选且已部署应用支持共享查看。符合条件但发布地址缺失时不能回退到草稿。管理员继续可查看非精选应用，未部署时沿用原有静态预览。作者维持已有工具会话恢复、计划加载、首次提示词和构建后刷新链路，`view=1` 仅是原有导航参数。

历史加载仍复用现有分页接口，但增加独立 loading / empty / error 状态和重试；初始历史失败不能触发作者的自动生成。pageEpoch 隔离历史成功与错误，账号／应用切换重置分页和预览；原 iframe identity 与 AbortController 继续隔离迟到加载。

### 写入口双重守卫

普通非作者用只读说明替代输入区；部署、下载和可视化编辑不提供可用按钮。生成入口、暂停、初始发送、会话恢复及编辑等处理函数也校验身份；不只依赖按钮 disabled。普通非作者不调用计划接口，不绑定作者的本机生成快照。管理员仅保留现有详情管理能力，不能代替作者生成或部署。

不放宽后端生成、取消、下载、部署、更新、删除的现有权限。新增／复用测试证明已部署状态不会让这些写接口失去原有校验。

### 预览失败单独处理

非作者页面的加载状态独立于历史，提供加载、失败和重试。使用现有 iframe 加载标识、超时和同源 HTTP 探测；跨源时不绕过浏览器同源策略，不能宣称可识别全部跨源 HTTP 错误。普通非作者不注入可视化编辑逻辑。预览失败不请求模型，不部署，不切换到草稿。

## Risks / Trade-offs

- 历史开放包括已部署应用之后产生的展示对话 → 这是应用级历史查看，不新增“按发布日期截断”规则；内部摘要材料不外发。
- 取消精选、撤销部署字段或删除后继续翻页 → 每页重新授权，拒绝响应也受页面身份隔离。
- 草稿与发布版本混淆 → 非作者明确打开 deployUrl；作者已有预览逻辑保留。
- 仅 UI 禁用不足以授权 → 后端既有写接口验证，加直接越权调用回归。
- 原页面缺少明确错误状态 → 按历史与预览分别提示，保留分页和迟到响应测试。

## Verification

Java 使用现有离线 Maven 仓库与 JUnit/Mockito，覆盖普通用户、作者、管理员、未登录、参数异常、精选且已部署、仅部署、仅精选、均不满足、取消精选、半成品部署记录、删除／分页状态变化、跨应用查询及真实 HTTP 序列化；复用真实写服务入口验证拒绝发生于副作用之前。

前端用 Vitest 检查身份、发布预览选择及相关异步逻辑，执行原有会话、预览、计划、滚动和登录回归及类型检查。使用实际构建前端和隔离本机 HTTP 合成夹具进行浏览器验收：非作者精选且已部署、仅部署、仅精选、均不满足、空历史、历史失败重试、作者入口、账号／应用切换和预览失败。记录请求，断言没有生成、取消、部署、下载或计划请求。此测试不接触生产账号、数据库和付费模型。

证据保存在 `.codex/enable-deployed-app-readonly-view/`，正式索引及验收映射位于本变更 reports。独立评审者复核规划和当前实现；采用 machine 输入指纹。

## Migration Plan

无数据迁移。代码和测试完成后报告本地结果，发布需另外明确授权。回退时整体恢复本次历史授权与前端查看修改，不改写部署记录或历史内容。
