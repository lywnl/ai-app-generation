U2 的原规划、评审、验收及待修改实现已保留在 `.codex/enable-deployed-app-readonly-view/baselines/deployed-only/`。本轮逐项核对 `snapshot.json` 中 21 个备份文件：全部存在且 SHA-256 一致；三份受影响业务实现仍与备份相同，尚未将 U3 代码修改混入评审前状态。当前 `reports/verification.md` 已明确为 `Needs Work`，没有用旧验收证明新范围。

核实要点：

- 原始空白问题已在 U2 实现中处理；本轮有效变更是将“已部署即共享”收紧为“精选且已部署才共享”，不是恢复作者／管理员专属读取。
- 当前 `AppConstant.GOOD_APP_PRIORITY` 为整数 99，AppVO 与前端 API 类型已包含 priority。规划要求与非空白 `deployKey`、非空 `deployedTime` 联合判断，三个条件缺一不可；封面、`view=1`、单独精选或单独部署均不能替代该资格。
- 后端每页重新检查精选和部署状态，取消精选后的下一页必须拒绝。前端在普通非作者不满足联合条件时不加载发布或草稿 iframe；作者不受共享条件影响，管理员继续保留非精选应用的读取和适用预览能力。
- 历史实体的 `decisionEvidence` 已不序列化，而 `memoryMessage` 与 `memoryOutcome` 仍是作者接口可能返回的数据。仅为普通非作者复制展示字段既能隔离内部值，也能保留原接口及作者／管理员行为。
- 现有生成、取消、部署、下载、普通更新入口校验作者；删除另保留管理员权限。新增历史资格不需要改变这些写接口。计划客户端和服务端保留作者入口，普通非作者不应加载计划。
- `AppVO.deployUrl` 由后端部署地址构造器生成。非作者使用该地址能区分发布页面与后续草稿；先设置发布预览、再独立加载历史可以消除空历史／失败阻断预览的问题。

未检查生产账户、真实业务库或云端发布环境；未运行业务测试。规划已经将这些边界与隔离本机验收分开，没有把替身数据声明为生产证据。

## Warnings

以下均已在设计与规格中处理，不需要新增用户决定：

- 跨源 iframe 不能可靠获取所有 HTTP／资源错误。验收只能声明同源探测、加载事件和超时实际覆盖的情况，不把跨源 `load` 事件等同于全部资源正常。
- 部署记录说明曾成功部署，不保证发布资源此刻可访问。预览失败应独立提示和重试，不能回退到草稿，也不能因此误触发生成或部署。
- 本变更不调整既有静态资源公开策略。交付时应准确表述为精选且已部署应用历史的读取授权及查看页预览资格，不能宣称拦截了所有直接发布 URL 或新增了全站未部署源码访问控制。
