## Purpose

将后端已经识别的模型服务故障转换为用户可以理解并采取行动的提示，在生成前置失败、生成中终止和普通接口响应之间保持一致，同时继续保护服务商原始响应与系统内部信息。

## ADDED Requirements

### Requirement: 明确识别模型余额不足

系统 SHALL 根据模型 SDK 异常及其因果链中的 HTTP 402、明确余额不足错误码或明确余额错误消息，选择固定提示“模型服务余额不足，请充值后重试。”。检查 SHALL 有界并防止循环；普通限流、鉴权、上下文不足、模糊配额错误和仅在任意业务文本中提到余额的情况不得据此归类。

#### Scenario: 模型余额错误被多层包装
- **WHEN** 模型余额错误被 SDK、异步执行或回合分类异常包装
- **THEN** 系统仍可沿保留的 cause 识别余额不足并生成固定提示

#### Scenario: 未知错误与伪余额文本
- **WHEN** 故障没有明确余额证据，或非模型异常仅在文案中出现余额字样
- **THEN** 保留该入口原有通用提示，不暴露内部异常文本，也不将限流等错误误报为余额不足

### Requirement: 前置和普通接口显示余额提示

系统 SHALL 在生成开始前的安全错误响应及普通 JSON 异常响应中使用已识别的余额提示。既有错误码、错误类别、SSE 字段、done 序号和前置资源清理语义 SHALL 保持兼容。

#### Scenario: 分类模型在用户消息提交前余额不足
- **WHEN** 回合分类因余额不足失败
- **THEN** 返回包含明确余额提示的 business-error 和一次 done，不写入该次用户消息或启动生成，并释放已取得资源

#### Scenario: 普通接口遇到模型余额不足
- **WHEN** 模型余额错误到达普通 JSON 异常处理入口
- **THEN** 返回原响应结构和错误码，message 为固定余额提示

### Requirement: 生成中余额失败保持一致终态

系统 SHALL 在 Vue 与普通生成因余额不足失败时向前端发送明确提示，并在新产生的失败展示记录中保持该原因。Vue 可信投影 SHALL 使用服务端分类的余额不足原因。取消、协议错误、真实构建结果、唯一终态和资源释放优先级 SHALL 保持现状，失败不得刷新预览。

#### Scenario: Vue 生成或提交后启动时余额不足
- **WHEN** 用户消息已经提交，模型调用或生成启动因余额不足失败
- **THEN** 唯一失败终态的客户端提示及持久化展示包含余额原因，可信投影不接收原始异常，预览不刷新

#### Scenario: HTML 或多文件生成时余额不足
- **WHEN** 普通生成流报告已识别余额错误
- **THEN** 安全错误与新失败记录使用一致余额提示，并按现有失败路径结束与释放资源

### Requirement: 前端展示后端明确提示

前端 SHALL 将余额错误帧中的安全 message 用作失败提示，不用通用“系统内部错误”覆盖；现有 SSE 协议校验、按钮恢复和预览规则 SHALL 保持不变。

#### Scenario: 前置或流式余额错误到达前端
- **WHEN** 前端收到合法的余额 business-error 或失败 turn-outcome 并收到 done
- **THEN** 会话结束加载，保留该错误 message，不误标成功或触发预览刷新
